## 零、这个站和 blog 有个根本区别

| | **universe**（本站） | blog（对比） |
|---|---|---|
| `assets.directory` | `./src` | `./dist_pages` |
| 有构建步骤吗 | **没有** | 有（Python 九步管线） |
| 改完就能部署吗 | **能** | 要先跑构建 |

**`src/` 里的文件就是最终产物** —— 改了 `src/index.html`，push 上去就是新版。

所以本站**没有** blog 那个「改了前端要重跑 pages 步」的坑。
**代价**是：改坏了没有构建环节拦你，所以**必须靠探针**（见第五节）。

## 一、三步法（标准流程）

```powershell
# ① 改
cd /d D:\QX_t1me_plan\02-universe
#    直接编辑 src/index.html / src/css/style.css / src/js/app.js

# ② 本地看效果（务必）
cd /d D:\QX_t1me_plan\02-universe\src
python -m http.server 8802 --bind 127.0.0.1
# 浏览器开 http://127.0.0.1:8802

# ③ 发布
cd /d D:\QX_t1me_plan\02-universe
git add -A
git commit -m "描述这次改了什么"
git push
# → 约 1 分钟后 Cloudflare 自动部署
```

**不需要任何构建命令。** push 到 `main` 后，Cloudflare 的 Git 集成
（Workers Builds）读 `wrangler.jsonc` 的 `assets.directory: ./src` 直接部署。

## 二、改了什么 → 要注意什么

| 你改了什么 | 要注意 |
|---|---|
| **文案**（`data-zh` / `data-en`） | 两语都要改，否则切英文时露中文 |
| **CSS**（`src/css/style.css`） | 改完跑主探针（配色判据会当场发现跑偏） |
| **JS**（`src/js/app.js`） | **必须**跑交互探针（行为变了它才抓得到） |
| **HTML 结构** | 跑主探针 + 交互探针，两者都涉及结构守卫 |
| **加一个新站入口** | 加 `<a>` 到「站点」栏；探针会验「一个站只出现一次」 |
| **字体**（`src/css/fonts.css`） | ⚠️ 这文件是**机械抽取**的，别手改；改字体要动 `_tools/extract_fonts.py` |

## 三、⚠️ 站点家族的三条规矩（改之前要知道）

### 规矩 1：界面零彩度，颜色只来自内容

universe 的 UI **一点色相都不带** —— 只有暖黑 `#0f0f0f` / 暖白 `#f2f1ed` 与灰阶。
加彩色 UI 元素会破坏三站家族的一致性。

### 规矩 2：一个站只出现一次

universe 是**站群入口**，同一个 URL 不该在页面上出现两次。
曾经有过「影集 / 延时 / 闲聊 / 每日颜色 / 关于我 / 音乐 / 联系」七条全指向 blog 首页 ——
同一站列七遍，且都不通向各自声称的页面。**删掉两栏才解决。**

要加新入口：在「站点」栏加一条 `<a>`，**不要**在别处重复列同一个站。

### 规矩 3：站点自身的内容，不重复子站的内容

「关于本站」讲的是 **universe 自己**（它是什么、和子站什么关系），
不是复述 blog 有什么。违反这条会变成「同一批内容在两个站各讲一遍」。

## 四、字体特别说明

`src/css/fonts.css` 是 `_tools/extract_fonts.py` 从 blog 的 `style.css`
**机械抽取**出来的（blog 的衬线按 `unicode-range` 切成 core/rest 两片，
声明区 170 多行字符区间，手抄必然出错）。

```powershell
# 改字体要这样：改 blog 的 CSS → 重新抽取
cd /d D:\QX_t1me_plan\02-universe
python _tools\extract_fonts.py
```

该脚本按「与本站平级的 `01-blog`」自动找源文件，
也可以用环境变量 `BLOG_CSS` 覆盖。

> ⚠️ **`unicode-range` 换行只能落在逗号后** —— 违反会被浏览器
> **静默丢弃整条声明**，表现为字体悄悄退回系统宋体，肉眼很难发现。

## 五、验收：三套探针（本站的"安全网"）

因为没有构建环节，**探针就是唯一的防线**。三套分工不同：

| 探针 | 管什么 | 条数 |
|---|---|---|
| `probe_universe.js` | 静态结构与配色（含与 blog 的令牌比对） | 64 |
| `probe_interact.js` | 交互行为（弹窗 / 复制 / 磁贴 / 天气） | 34 |
| `probe_geo.js` | 定位分支（伪造坐标验授权路径） | 4 |

### 跑法

两个探针都依赖 `ws`，**必须先设 `NODE_PATH`**：

```powershell
# 起本地服务（探针默认打 127.0.0.1:8802）
cd /d D:\QX_t1me_plan\02-universe\src
python -m http.server 8802 --bind 127.0.0.1

# 另开一个终端
set NODE_PATH=D:\dsh_blog_proj\_tmp_eval\node_modules
cd /d D:\QX_t1me_plan\02-universe
node _tools\probe_universe.js      # 主探针
node _tools\probe_interact.js      # 交互
```

### 验线上

```powershell
set NODE_PATH=D:\dsh_blog_proj\_tmp_eval\node_modules
set PROBE_URL=https://universe.qxt1me.dpdns.org/
cd /d D:\QX_t1me_plan\02-universe
node _tools\probe_universe.js
node _tools\probe_interact.js
node _tools\probe_geo.js
```

> `probe_geo.js` 默认就打线上（本地 `127.0.0.1` 不是安全上下文，
> `navigator.geolocation` 不可用）。

**上线后应当看到**：三套全绿（64/34/4）。

## 六、手动部署（Git 集成挂了时的备用路径）

```powershell
cd /d D:\QX_t1me_plan\02-universe
npx --yes wrangler@4 deploy
```

⚠️ **必须钉 `@4`**：wrangler v3 不支持 `assets` 配置**且不报错**，
会静默跳过整个资源目录，只上传一个空壳 Worker 并报告成功。

**判据**：输出里必须有一行
`✨ Read N files from the assets directory`（本站当前为 **13**）。

> 📌 这个数字 = **10 个文件 + 3 个子目录**，wrangler 把目录也计入了。
> 所以它比你以为的「文件数」大一点，这是正常的 —— 别拿它当纯文件数核对。

> `package.json` 里 `wrangler: ^4.147.0` 是宽松范围，可能升到 v5。
> 手动部署时**一律显式写 `wrangler@4`**，别依赖它。

## 七、天气（本站唯一的外部依赖）

「站点」卡片里的天气走 **Open-Meteo**（免费、无 key、不设 cookie），
用访客定位；失败落到成都兜底。

> ⚠️ **这是作者批准的架构例外**：本来的铁律是「页面不引外站」，
> 天气打破了它。主探针的白名单里只有 `api.open-meteo.com` 一个 ——
> **再加别的外站会红**。

如果哪天想撤掉天气，除了删 `src/index.html` 的 `#weather` 块和
`app.js` 的第 7 段，**还要**把 `probe_universe.js` 里的 `WEATHER_API`
白名单与那条正向断言一并删掉，否则探针会失去意义。

## 八、常见问题

**Q：push 了但线上没变？**
→ ① 等 1–3 分钟；② 看 Cloudflare 构建记录；
③ 确认 push 的是 `main` 分支；④ 硬刷新浏览器（`Ctrl+F5`）—— CSS/JS 有缓存。

**Q：本地看着好，线上不一样？**
→ 大概率是**缓存**。本站 `_headers` 给 CSS/JS 设了 1 小时缓存
（无内容指纹，不能 immutable）。硬刷新，或看 Cloudflare 的 `CF-Cache-Status`。

**Q：改了 JS 但探针全绿？**
→ 检查探针是不是在测**旧行为**。判据要跟着改 —— 但也别为了让它绿就放宽判据，
先判断「是产品错了还是判据过期了」。

**Q：想撤回一次发布？**
→ `git revert` 那个 commit 再 push。**不要** `git reset --hard` 后强推。

**Q：可以直接改 `_shots/` 里的东西吗？**
→ 那是探针截图，已 gitignore，随便动。
